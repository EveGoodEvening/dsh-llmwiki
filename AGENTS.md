# Project Guidance

## Lessons

- As of 2026-08-16, this repository's controlled npm package name is `@evegoodevening/dsh-llmwiki`; the unscoped `dsh-llmwiki` remains a different project (`chancelu/dsh-llmwiki`) and must never be used for this implementation. npm/pnpm pack the scoped package as `evegoodevening-dsh-llmwiki-<version>.tgz`.
- Install out-of-tree DSH profile bundles with `dsh plugin --profile <name> add <package-spec>`. The command runs pnpm in the profile directory and reconciles packages declaring `dsh.bundle` into `dsh.profile.bundles`; plain `pnpm add` does not perform that activation step.
- DSH profiles intentionally set `autoInstallPeers: false`; installing this bundle therefore prints missing-peer warnings even when the running DSH supplies compatible host peers through its healed `$DSH_HOME/profiles/node_modules` fallback. Treat a successful profile boot as the compatibility proof, not `pnpm peers check`.
- As of 2026-08-23, `llmwiki_status` is strictly non-creating: it acquires safe paths without initialization, returns `initialized: false` with zero counts, `schemaText: null`, and an absent index for a missing root, and reports partial layouts without repairing them. Preserve direct service, tool, packed-package, and smoke coverage for this read-only contract.

The packaged-profile E2E matrix booted top-level hosts `@deepseek-ai/dsh@0.1.0-rc.6` and `0.1.1-rc.2`, verified every tool/command/prompt surface and the add-disable-remove-readd lifecycle, and asserted the actual resolved service family. A fresh install of the legacy `0.1.0-rc.6` host resolved its DSH service packages to `0.1.0-rc.8`; do not assume the top-level host version equals every runtime package version.
- As of 2026-08-30, DeepSeek Harness provides the plugin architecture but no official `llmwiki` behavior specification; evaluate this package separately on (1) DSH bundle/service/tool integration and (2) Karpathy's core persistent-compounding ingest/query/lint workflow. Passing Loader/profile E2E proves the first, not the second.
- As of 2026-09-03, v1 index trust is semantic rather than merely structural: status, lint, and search rebuild the page-derived expected index and byte-compare both `search.json` and `state.json`, so a forged canonical pair with current page fingerprints is rejected and search repairs it. This correctness choice also makes those freshness checks scan and rebuild the full page corpus before reusing persisted index bytes.
- As of 2026-09-03, the model-facing API can enumerate sources and pages through deterministic paginated catalogs and the repository contains a credentialed real-agent maintenance/recovery smoke harness. With no committed `tests/fixtures/agent-smoke/latest.json`, and without a query-answer/write-back workflow or general semantic-lint engine, continue describing the package as an llmwiki storage/retrieval substrate rather than a complete realization of the LLM Wiki idea.
- As of 2026-09-03, `readSource` and `readPage` still use the initializing service path: a missing-page read creates the root, `schema.md`, `sources/`, `pages/`, and `.index/` before returning `PAGE_NOT_FOUND`, despite their model-facing descriptions saying `Read-only`. Source records left partial across a process crash are not self-healing on same-content retry, and page upserts have no expected-hash precondition, so concurrent stale writers can overwrite one another.

Local proof can use a disposable root container with `CAP_SYS_ADMIN` and mount operations permitted; never silently skip this test.

- Token spans are UTF-16 slice boundaries in the already normalized body, not UTF-8 byte offsets. Only selected ranked hits receive excerpts; persisted index bytes and scoring remain unchanged.
